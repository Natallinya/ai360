## 1. Выбор проекта

**Идея:** агрегатор вишлиста — пользователь ищет товар текстом или по ссылке, видит варианты с разных площадок, сохраняет в личный список.

**Почему этот проект хорош для обучения Cursor:**

- Понятная продуктовая история (не «ещё один todo»).
- Есть и **фронт** (Angular), и **бэкенд** (BFF) — фронтендер учится fullstack без ручного погружения.
- Реальные ограничения: API маркетплейсов, легальность, SSRF — агент не выдумывает «магию».
- Можно показать эволюцию: идея → BA-док → MVP → интеграции → монорепо.

---

## 2. Как придумался

1. Нужен **пэт-проект** под стек **Angular 21** и публикацию на **GitHub**.
2. Рабочая папка **ai360** + Cursor как «со-разработчик».
3. Сначала — **бизнес-описание** (роль BA у агента), потом код, а не наоборот.
4. Интеграции выяснились итеративно: eBay → Allegro → DummyJSON + «по ссылке».

**Формула:** *идея в голове → один чёткий промпт → спецификация → scaffold → фичи по одной*.

## 6. Как шёл процесс (паттерн вайбкодинга)

1. **Один запрос — один слой:** сначала идея/BA, потом scaffold, потом фича.
2. **Правила рано:** после MVP — `.cursor/rules`, чтобы агент не «плыл» по структуре.
3. **Проверка реальностью:** «подключи Allegro» → агент исследует → честный отказ + альтернатива.
4. **Монорепо позже:** когда надоело два терминала — `npm run dev` из корня.
5. **Человек точечно:** push на GitHub, `npm run dev`, «порт занят», «сделай доклад».

**Промпты, которые сработали:**

- «Опиши идею как бизнес-аналитик»
- «Создай Angular 21 и подключи GitHub»
- «Добавь rules: components в папке components, суффикс .component»
- «Реализуй BFF и добавление по ссылке»
- «Объедини в монорепо»

---

## 7. Что помогало (инсайты, вау)

- **BA до кода** — меньше переделок, понятный scope MVP.
- **AGENTS.md + rules** — агент помнит структуру `pages/`, `components/`, ветку `development`.
- **BFF** — фронтендер не кладёт секреты в Angular; один `/api` через proxy.
- **Честные «нет»** по API — доверие к агенту выросло (Allegro, Ozon).
- **Монорепо `npm run dev`** — ощущение «настоящего» проекта одной командой.
- **Доки как артефакт доклада** — не только код, но и история решений.

---

## 8. Что смутило (опасения, раздражения)

- **Порты 4200/3000/4077** — старый `ng serve` висит в фоне → `EADDRINUSE`.
- **fetch failed** на Ozon — выглядит как «сломалось», на деле антибот маркетплейса.
- **Два мира:** фронтендер привык к `ng serve`, BFF — отдельная ментальная модель.
- **Агент не пушит без просьбы** — правильно, но нужно помнить про `git push`.
- **Иллюзия «всё через API»** — маркетплейсы закрыты; продуктовая правда важнее демо.

## 9. Вывод

**Эффективность Cursor для фронтендера:**

- За 1–2 сессии: спека + Angular + GitHub + 4 экрана + BFF + доки.
- Роль смещается с «пишу каждую строку» на «архитектор + ревьюер + продукт».
- Fullstack и DevOps-lite доступны без месяцев учебы — с контролем через rules и ревью.

**Сложность:**

- Интеграции с внешним миром (API, CORS, SSRF, блокировки).
- Дисциплина: правила, ветки, не коммитить секреты.
- Нужно понимать *что* принять от агента, а не слепо мержить.

## 15. Структура выступления (5–10 мин)

1. **Зачем** — пэт + обучение Cursor (30 сек)
2. **Идея** — вишлист-агрегатор (30 сек)
3. **Демо** — поиск `phone`, вишлист, add-by-url с тестовой ссылкой (2 мин)
4. **Как делали** — BA → rules → BFF → монорепо (2 мин)
5. **Вау / боль** — скорость vs API маркетплейсов vs порты (1 мин)
6. **Вывод** — фронтендер + агент = fullstack MVP (1 мин)
7. **Q&A** — репозиторий на экране

**Демо-скрипт:**

```text
1. npm run dev (из корня ai360)
2. localhost:4200 → поиск «phone»
3. Добавить в вишлист → вкладка Вишлист
4. По ссылке → кнопка «Демо-книга» → добавить
5. Показать GitHub + docs/PRODUCT_SPEC
```
