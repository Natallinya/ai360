# Продуктовая спецификация: агрегатор вишлиста с поиском по маркетплейсам

**Рабочее название:** WishCompare / «Мой вишлист»  
**Версия документа:** 0.1 (концепт)  
**Дата:** 2026-06-01  
**Целевой стек (технический контекст):** Angular 21, GitHub, Cursor / ai360  

---

## 1. Elevator pitch

**Веб-приложение**, в котором пользователь описывает желаемый товар текстовым запросом, получает **подборку предложений с разных торговых площадок**, сравнивает варианты и **добавляет выбранные в личный вишлист** — без покупки внутри приложения (переход по ссылке на магазин).

**Ценность:** один запрос → несколько площадок → один список желаний с ценой, ссылкой и статусом («в наличии / подорожало» в будущих версиях).

**Не является:** маркетплейсом, корзиной, платёжной системой, гарантом лучшей цены.

---

## 2. Проблема и возможность

| Проблема | Как продукт решает |
|----------|-------------------|
| Идея подарка/покупки размазана по закладкам, чатам, скриншотам | Единый вишлист с метаданными |
| Один и тот же товар ищут вручную на Ozon, WB, Я.Маркете и т.д. | Один поиск → сводная выдача |
| Сложно сравнить «похожие, но не те же» предложения | Карточки с ценой, магазином, ссылкой; позже — сопоставление одного SKU |
| Вишлист для друзей/семьи неудобен | Публичная ссылка на список (фаза 2) |

## 3. Целевая аудитория

### Первичные персоны (MVP)

**П1 — «Планировщик покупок»**  
25–40 лет, сам себе составляет список желаний перед зарплатой/распродажей. Нужны поиск, сохранение, сортировка по цене.

**П2 — «Получатель подарков»**  
Делится вишлистом с близкими. Нужны понятные ссылки и актуальная цена (фаза 2).

### Вторичные (позже)

- **П3 — Куратор подарков** (друг/родственник): только просмотр чужого списка.
- **П4 — Партнёр/аффилиат** (если монетизация): переходы по affiliate-ссылкам.

### География

Выбор региона влияет на доступные API:

- **RU:** Ozon, Wildberries, Яндекс Маркет, DNS, М.Видео и др.
- **Global:** Amazon, eBay, AliExpress и др.

Для MVP лучше **явно выбрать один рынок**, иначе интеграции и юридика разъедутся.

## 6. Основной пользовательский поток (Happy Path)

```
[Главная: поле запроса]
        ↓
[Поиск по адаптерам площадок]
        ↓
[Сводная выдача]
        ↓
   ┌────┴────┐
   ↓         ↓
[В вишлист] [Сайт магазина]
   ↓
[Страница вишлиста]
   ↓
[Редакт / удалить / куплено]
```

**Шаги:**

1. Пользователь вводит запрос (например: «электрическая зубная щётка Oral-B»).
2. Backend параллельно опрашивает **подключённые источники** (адаптеры).
3. Frontend показывает **единый список карточек** (нормализованная модель).
4. Пользователь нажимает **«В вишлист»** → сохраняется снимок: название, цена на момент добавления, URL, площадка, картинка, external_id.
5. На странице вишлиста — все сохранённые позиции, кнопка «Перейти в магазин».

## 8. Единая модель данных (концепт)

### `ProductOffer` (результат поиска)

| Поле | Описание |
|------|----------|
| `id` | Внутренний UUID |
| `source` | `ozon` \| `wildberries` \| `ebay` \| `mock` … |
| `externalId` | ID на площадке |
| `title` | Название |
| `price` | Число + `currency` |
| `imageUrl` | Превью |
| `productUrl` | Deeplink на карточку |
| `availability` | `in_stock` \| `unknown` |
| `fetchedAt` | Время получения |

### `WishlistItem` (сохранённое желание)

| Поле | Описание |
|------|----------|
| `id` | UUID |
| `userId` | Владелец |
| `offerSnapshot` | Копия `ProductOffer` на момент добавления |
| `note` | Комментарий пользователя |
| `status` | `active` \| `purchased` \| `archived` |
| `addedAt` | Дата |

**Важно:** в вишлист сохраняется **снимок**, а не живая связь с API магазина — иначе при падении интеграции список «ломается». Обновление цен — отдельная фича (фаза 2).

## 9. Интеграции с площадками — реалистичная картина

### 9.1. Типы API

| Тип | Примеры | Подходит для поиска? |
|-----|---------|----------------------|
| **Seller API** | Ozon Seller, WB API продавца | **Нет** — только свои товары продавца |
| **Affiliate / Product API** | Amazon PA-API, eBay Browse API | **Да**, с ограничениями и одобрением |
| **Агрегаторы** | SerpAPI, RapidAPI, affiliate-фиды | **Да**, часто платно |
| **Парсинг сайта** | Custom scraper | Технически да, **юридически рискованно** (ToS) |

### 9.2. По площадкам (кратко)

| Площадка | Публичный поиск для стороннего приложения | Комментарий для MVP |
|----------|-------------------------------------------|---------------------|
| **Ozon / WB / Я.Маркет** | В основном **API продавца**, не B2C-поиск | Без партнёрства — не как первый источник; варианты: affiliate, URL, mock |
| **eBay** | [Browse API](https://developer.ebay.com/api-docs/buy/browse/overview.html) | Sandbox доступен; **production — одобрение eBay** |
| **Amazon** | Product Advertising API | Affiliate-аккаунт, жёсткие правила отображения |
| **AliExpress** | Affiliate / openapi ограниченно | Часто через партнёрские сети |

**Вывод:** обещание «найдём на всех маркетплейсах с первого дня» нереалистично. Корректнее: **«поддерживаемые площадки»** с явным списком и постепенным расширением.

### 9.3. Стратегия источников по фазам

**Фаза 0 (прототип):**

- Mock-адаптер + 1 реальный источник с легальным API (eBay sandbox или статический JSON).

**Фаза 1 (MVP):**

- 1–2 легальных источника + **«Добавить по ссылке»** (URL → Open Graph / meta).

**Фаза 2:**

- Affiliate-фиды / платный агрегатор под регион.
- Дедупликация «один товар — несколько магазинов».

**Фаза 3 (RU):**

- Партнёрские программы Ozon/WB/Яндекс — не скрапинг «втихую» для продакшена.

## 10. Нефункциональные требования

| Категория | Требование |
|-----------|------------|
| **Производительность** | Первые результаты ≤ 2 с; полный ответ ≤ 8 с (таймаут по источнику) |
| **Надёжность** | Падение одной площадки не ломает всю выдачу |
| **Безопасность** | API keys только на backend; HTTPS |
| **Юридическое** | Ссылки на магазин; affiliate guidelines; privacy policy |
| **Доступность** | Базовая a11y для форм и списков |
| **SEO** | Landing + публичные вишлисты (фаза 2) — SSR / prerender |
| **Масштаб (пэт)** | До ~1k пользователей без сложной инфраструктуры |

## 11. Границы MVP (рекомендация)

### В scope MVP (4–8 недель соло)

- Angular 21: главная (поиск), результаты, вишлист
- Backend (BFF): единая точка для секретов API
- **2 режима поиска:**
  1. Mock + один реальный источник (eBay sandbox или JSON-каталог)
  2. **«Добавить по ссылке»**
- Guest + localStorage или простой auth
- GitHub + CI + хостинг (Pages/Cloudflare + Railway/Render)

### Вне scope MVP

- Автопоиск по Ozon/WB без партнёрского доступа
- Сопоставление «один товар на разных площадках»
- Push об изменении цены
- Мобильное приложение
- Оплата внутри приложения

## 13. Бизнес-правила

1. В приложении **не** обещаем «гарантию лучшей цены» — только «цена на момент запроса».
2. Каждая карточка **явно помечена** площадкой и ведёт на **внешний** URL.
3. Дубликат в вишлисте = тот же `productUrl` для одного пользователя.
4. Результаты поиска кэшируются с TTL (15–60 мин).
5. При недоступности источника — badge «площадка временно недоступна».

## 14. Риски и допущения

| Риск | Влияние | Митигация |
|------|---------|-----------|
| Нет легального API для RU-маркетплейсов | Нет поиска по Ozon/WB | MVP: URL + mock; фаза 2: affiliate |
| Разные названия одного товара | «Дубли» в выдаче | Принять в MVP; умное слияние позже |
| Блокировка scraper | Пустая выдача | Только официальные каналы |
| eBay/Amazon production access | Задержка | Sandbox + mock |
| Юридические претензии | Закрытие проекта | ToS, партнёрские соглашения |

**Допущения:**

- Покупка завершается на стороне магазина.
- Монетизация на старте не обязательна.
- Язык UI: RU (или RU + EN — зафиксировать).

## 16. Pitch (один абзац)

> **Wishlist Aggregator** — персональный вишлист с умным поиском: пользователь описывает желаемый товар, система собирает предложения с подключённых интернет-магазинов в единой ленте, а пользователь одним действием сохраняет понравившийся вариант в свой список желаний с ценой, фото и прямой ссылкой на покупку. Приложение не продаёт товары, а помогает **найти, сравнить и не забыть** — с постепенным подключением новых площадок через легальные API и партнёрские программы.
